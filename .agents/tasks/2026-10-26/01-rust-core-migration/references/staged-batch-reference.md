## Authoring gate

1. Protect actual response-owner port bytes, conditional discovery authority,
   metadata/pending failure barriers, recipe clocks, and retry outcome differences.
2. Credible regressions: wrapping legacy output, treating duplicate failure saves
   as successful, using a prior pending read, substituting negotiated for stored
   version, eager clocks, or dispatching handlers after a failed precondition.
3. Reuse `opcode-plan-v1.json` grouping/index/hash answers and
   `TestOpcodePlanCompatibilityAtResponseHandler`; existing discovery tests cover
   coalesced fan-in and always-retry. New cases add literal saved bytes and full
   queue recipes at those ports, and otherwise-uncovered metadata/version/fault
   branches. Retain lifecycle, recovery, wait/invoke/gateway/defer regressions.
   Do not copy their store/recovery harness.
4. No production seam. Same-package tests call real `HandleGeneratorResponse`,
   `GeneratorOpcode.Output`, grouping/hash and option owners; recording services
   only return supplied effect outcomes. No standalone planner.

## Scope and staging contract

Candidate: whole recognized, non-null batches of None, Step, StepRun, StepError,
StepFailed, StepPlanned, Sleep. Future unsupported mixed batches remain entirely
Go; this corpus does not implement that routing. All-empty None redrive before
this entry, parser errors, nil descriptors, missing internal errors, function
completion, wait/signal/invoke/gateway/defer are outside candidate. In particular
missing StepError.Error is dereferenced before the nil check today; do not give
that invalid input a new success/failure meaning.

Inputs retain ordered descriptors, raw data (including absent/null distinction),
errors/options/opaque IDs plus minimal metadata, policy, attempts, edge/queue
context. No copied event history. External observations are separate from input:
accepted metadata/pending writes, SaveStep `(hasPending,error)`, enqueue outcomes,
clock observations, generated UUIDs and trace carriers.

A future intention representation must suspend at: metadata proposal -> accepted
write -> step limit -> grouping/shared handling observation/coalesce -> accepted
SavePending -> concurrent sibling recipes -> group barrier. Each save recipe
branches on the actual returned SaveStep result before lifecycle/release/discovery.
No speculative effect list or per-opcode crossing is authorized. Output building
and trace preparation can themselves fail before SaveStep. State size is an
observation, never a reservation. Sibling returned error is nondeterministic.

The bounded evidence and stopped cost/extraction gaps are recorded below.

**Stopped at the accepted boundary.** Beyond grouping/hash and output wrapping,
current recipe work is largely cheap templates/predicates. No pure whole-response
owner exposes metadata negotiation, validation and every conditional recipe
without interleaved effects. A full matched cost baseline, bridge projection,
intention validation and materialization cost are therefore **unmeasured**.
Response/raw/output byte counts do not price those missing operations. The tests'
recording adapters must never be benchmarked as pure planning. Payload wrapping
has measurable work, but says nothing about net native savings after byte movement,
validation, and Go output materialization. No full matrix, threshold relaxation,
Rust/bridge implementation, per-opcode crossing, or owner migration follows.

Concrete extraction proposal for separate parent acceptance: keep every effect
activation point in the current Go interpreter. Factor pure metadata proposal,
ordered grouping/pending proposal, and separate successful-save, failed-save,
planned, and sleep recipe builders **at their current activation sites**.
Builders consume minimal projections and external generated-value/clock bindings,
return errors at the same sites, and carry conditional continuations that Go
activates using actual write outcomes. A batch representation would have to
encode those continuations once, including per-save pending/error policies and
nondeterministic sibling joins, so it never requires an extra crossing per opcode.
Do not eagerly sample absolute/relative clocks or validate output before accepted
metadata/pending writes. First benchmark the extracted Go-only owner, required
projection/validation/materialization and byte copies on identical workloads;
only then decide whether useful movable work exists. This proposal is not
implemented or accepted here. CEL, SDK requests, JCS and queue algorithms retain
their existing owners.

## P2 sibling barrier repair and independent review (accepted)

Independent Luna round one, `rust-staged-batch-review-01`, found the sole P2 in
`TestStagedBatchSiblingJoin`: only b blocked, so a sequential loop processing
both siblings and returning the first error could pass. The prior entry signal
also preceded the error return; the old concurrency/join claim was too strong.
The other reviewed corpus families and component-cost STOP were accepted in
principle. Sol repaired the barrier, and independent Luna round two found no
blockers. Luna reran normal and race validation, inspected both mutation logs,
confirmed production restoration SHA
`f9a53b9fee1eda4534b6e3814b0f9f7c0126e4b402c732db16a4ec7d09338e88` with no
production diff, and confirmed prior corpus/evidence remained preserved. Parent
acceptance is for this bounded Go corpus only; the extraction proposal below
still needs separate implementation and review.

Authoring gate for this repair:

1. Protect concurrent sibling dispatch and response-owner completion only after
   all siblings finish, including the supplied SaveStep failure path.
2. Reject serial processing of every sibling and returning on first completion
   while another sibling remains blocked.
3. Repair this primary owner test: existing literal event/byte fixtures and
   discovery fan-in checks do not distinguish serial dispatch or early return.
4. No production or support seam. Reuse `newStagedBatch`, existing recording
   store/events and real `HandleGeneratorResponse`/handler/group owners; use the
   standard `testing/synctest` available at the repository's Go 1.26.4 minimum.

Both saves now block on separate bubble-local channels; an order-independent
entry multiset must contain a and b **before either channel is released**.
Release a with `context.Canceled` while b stays blocked. `synctest.Wait` drains
runnable work until other bubble goroutines exit or are durably blocked. In this
fixture a has no remaining durable blocking point after its failed SaveStep, so
quiescence lets its real handler return through dispatch and into the group.
The buffered channel recording the actual `HandleGeneratorResponse` return must
remain empty. After b is released, quiescence must produce the error result and
b's finished lifecycle event. This is not a before-return error notification or
a timed opportunity to run; it proves this fixture's failed-save/join path,
without selecting between competing sibling errors or covering every possible
error branch. The standard library's durable-blocking semantics also avoid
asserting a scheduler interleaving.

Deferred idempotent releases run even on Fatal and quiescence drains remaining
workers before the bubble exits, including orphaned workers under the early
return mutation. Reads occur after quiescence; recorders retain their mutexes.
The old real-time 20ms window and 2s channel timers are removed. All probes and
final tests have `-timeout=60s` (and a 120s subprocess bound); quiescence replaces
scheduler sleeps and timing-based assertions.
